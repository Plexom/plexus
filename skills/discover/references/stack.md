# Offering the stack

Read by `[stage2]discover` when its technical round begins — the stack, or any choice that
shapes what the product can be. The rest of discovery never needs it.

**The stack — and any choice that shapes what the product can be — is never offered from
memory.** Before the question, find out what is current for this kind of product and for
the effects the spec asks for: an agent with sources and dates when research is on or
private, the limits of what you know said aloud when it is off. The options are the
strongest of what exists today, not the first three that come to mind; an option the user
named themselves is always among them. Each says, against the spec's own wishes, **what the user gets and
what they cannot get**:

```
three.js + bloom        the glow bleeds and mixes like in synthwave games, particles,
                        3D camera; ~600 KB library, a GPU does the work — gets hot on
                        an old laptop
Canvas 2D, no library   ~40 KB, runs anywhere; the glow is a drawn halo around each
                        block, it never blends into one light
```

**The search covers the new as well as the proven.** Besides what is established, look for
what appeared or matured in the last year or two and fits the spec — a new engine, a
runtime, a library that does in a line what used to take a hundred, an approach still
marked experimental. When one fits, it is among the options, never dropped for being
unfamiliar; when none does, say in a line that you looked. Each option carries its
**maturity**, from the sources and with dates: stable since when, current version, who
maintains it and how actively, how widely it is used. And the costs that come only with
the new, said plainly, not buried:

- it changes under you — breaking releases, an API that moves;
- fewer answers when something breaks — examples, questions answered, people who know it;
- **the agents know it less** — what came out after a model's training is written from
  documentation fetched each time, slower and with more mistakes, and the tasks built on
  it are checked harder;
- the way back — what it costs to leave it if it does not hold.

```
Bun + Hono          starts in ~20 ms, one tool instead of five; stable since 2023,
                    moves fast — a minor release can break a build; fewer answers
                    when stuck; the agents know it less and fetch its docs each time
Node + Express      what everyone knows, answers to anything; slower to start,
                    more tools to set up
```

The recommendation follows the priorities the user set in the earlier rounds, and says
which one decided it. A new or experimental option is recommended only when those
priorities call for what it gives, never for novelty; when it is chosen, its decision
records the maturity it was chosen at, and its "Revisit if" names what would make it a
mistake — "a breaking release in the next year", "the project is abandoned". With research
off, say that what came out after your training is unknown to you: new options cannot be
offered without looking.
